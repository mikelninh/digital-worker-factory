# OCN Go-to-Market & Discovery

**Commercial wedge:** sell measurable assurance around existing agents, not an abstract trust platform.

## 1. One-sentence pitch

> **Before your agent acts, OCN checks the evidence, authority, freshness and policy. After it acts, OCN leaves a verifiable receipt.**

For a technical buyer:

> **OCN is a model-neutral guard and assurance layer for agent actions: preflight checks, evidence-bound decisions, human/authority gates and post-action receipts.**

For government/public IT:

> **Keep your sovereign model, cloud and Fachverfahren. OCN adds reusable assurance around the agents you are already deploying.**

## 2. Do not lead with

- x402 or crypto;
- "AI safety" as an abstract category;
- a universal trust score;
- 160 planned capabilities;
- replacing the customer's existing agent stack;
- national-scale or billion-request claims before measured proof.

Lead with one costly workflow and one measurable failure mode.

## 3. First product: OCN Shadow Pilot

### Offer

Connect OCN to one existing agent/workflow in observation mode. OCN does not gain execution authority. It produces trust envelopes and a before/after evidence report.

### Best starting workflows

- application/document preflight;
- agent-generated decision/recommendation packets;
- policy/rule freshness checks;
- internal agents that write/send/approve/update data;
- agentic procurement/compliance workflows;
- regulated customer-service or operations agents.

### Pilot success metrics

- missing/weak evidence caught;
- stale rule/source caught;
- authority mismatch caught;
- unsupported output caught;
- human review minutes saved;
- human override rate;
- false-block / false-allow estimate;
- p95 latency overhead;
- integration time;
- audit completeness;
- cost per useful catch / trusted event.

### Commercial shape

- fast design-partner pilot: EUR 5k-15k where speed/reference value matters;
- institutional/government pilot: EUR 25k-50k for a bounded workflow with integration, evaluation and report;
- credit pilot fees toward an annual deployment when appropriate;
- do not promise regulatory certification.

Pricing remains a hypothesis until validated in buyer conversations.

## 4. Expansion path

### Shadow

Observe, measure and produce proof. No blocking authority.

### Enforce

Block only agreed deterministic violations; route ambiguous/consequential cases to authorized humans.

### Scale

Reuse the same trust contracts across more agents/workflows/providers. Add annual platform/managed-service/usage pricing.

## 5. Discovery questions

A qualified conversation should uncover:

1. Which agents are already in production or pilot?
2. What can those agents actually do: read, recommend, write, send, approve, pay or change records?
3. Which mistakes are expensive, embarrassing, unlawful or hard to investigate?
4. What currently makes a human review an agent output?
5. How do you know the source/rule used by the agent is current?
6. Where does authority/permission live today, and can the model influence it?
7. If an incident happens, can you reconstruct exactly what the agent saw, decided, was allowed to do and actually did?
8. What evidence does security/compliance/procurement require before autonomy can increase?
9. Which review step consumes the most staff time?
10. What measurable result would make a 30-day pilot an obvious success?

The goal is to find a real trust gap, not convince a buyer they need one.

## 6. Qualification signal

Prioritize buyers with at least three of these:

- active agent/LLM workflow;
- meaningful write/consequential capability;
- regulated or audited environment;
- high human-review burden;
- multiple models/agent platforms;
- stale policy/evidence risk;
- fragmented permissions;
- difficult incident reconstruction;
- desire to increase autonomy but governance blocks it;
- platform role serving many downstream teams/authorities.

## 7. Priority buyer segments

### A. Public IT providers / shared government platforms

Highest leverage because one integration can spread to many authorities.

Target: govdigital members and public IT providers, Agentic AI Hub ecosystem, sovereign AI/platform teams.

Ask: integrate OCN Shadow Mode around one shared agent workflow, then package it as a reusable assurance component.

### B. Agent platform / enterprise AI teams

Companies operating multiple agents need model-neutral controls, observability and audit.

Ask: wrap one production agent/tool path and measure trust gaps.

### C. Regulated enterprises

Healthcare, insurance, finance, legal/compliance, utilities and housing.

Ask: prove that OCN reduces manual review/incident risk while keeping authority outside the model.

### D. Agent developers / machine-native users

Use low-friction MCP/SDK/x402 distribution for high transaction frequency.

Ask: install Guard once; pay per trusted event automatically.

## 9. Outreach sequence

### Step 1 — discovery, not pitch

"We are testing a model-neutral assurance layer around agents already doing real work. I am looking for one workflow where stale evidence, weak authority or hard-to-audit actions are limiting autonomy. Can I understand how you handle that today?"

### Step 2 — show their own risk

Use their workflow in Shadow Mode. Do not begin with a generic demo.

### Step 3 — evidence review

Show exactly which actions were clean, which would require review, and why. Include false-positive adjudication.

### Step 4 — paid bounded pilot

Agree measurable success thresholds, data boundaries and authority boundaries before the pilot starts.

### Step 5 — expansion

Only after evidence: enforce deterministic gates, add more workflows, deploy sovereign/customer-controlled where needed.

## 10. North-star commercial metrics

- unique external paying agents;
- trusted events / external agent / day;
- 7-day and 30-day repeat payer rate;
- pilot -> enforcement conversion;
- enforcement -> multi-workflow expansion;
- useful issue catch rate;
- human review time saved;
- false-block / false-allow rate;
- revenue / 1,000 trusted events;
- gross margin / trusted event;
- p95 latency;
- number of workflows/authorities reached per integration partner.

## 11. Immediate target

The next commercial milestone is not "more capabilities".

It is:

> **One external organization connects one existing agent to OCN Shadow Mode and confirms that the trust evidence is useful enough to pay for continued use.**
