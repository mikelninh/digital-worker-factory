# OCN M0 → M12 Acceleration Plan

**Goal:** reach network-business proof as fast as evidence allows, without converting unproven claims into marketing.

## Principle

Some milestones are code milestones; others require external reality. We can parallelize them, but we cannot honestly self-generate an external buyer, a customer outcome, an independent audit or repeat market demand.

The fastest credible program therefore runs six lanes in parallel:

1. **Public rail** — hosting, discovery, payment, reliability.
2. **Assurance** — formal kernel, proof cards, evals, adversarial cases.
3. **Distribution** — MCP, JS SDK, Bazaar/Agentic.Market, AgentCore, Cloudflare.
4. **Design partners** — Shadow Mode on real workflows.
5. **Scale/sovereignty** — load evidence and customer-controlled deployment.
6. **Economics** — repeat paid events, expansion and unit economics.

## M2 — Public trust rail live 🟡 CRITICAL PATH

Exit evidence:
- stable public HTTPS endpoint;
- `/.well-known/trusted-events.json` reachable externally;
- `/v1/network/health` healthy;
- x402 testnet payment works externally;
- public proof registry links the exact build/version.

Fastest move: deploy the exact green Docker/network build to one stable public container/compute target. Do not wait for the final hyperscale platform.

## M3 — First horizontal trusted event live + public proof card 🟡 CRITICAL PATH

First candidates:
1. `freshness.verify.v1` — cheapest/fastest deterministic proof.
2. `authority.check.v1` — strongest trust invariant.
3. `payment.intent.preflight.v1` — clearest fraud/commercial wedge.

Exit evidence:
- public endpoint;
- paid external request;
- proof card showing what it proves/does not prove;
- CI/formal/eval version;
- measured latency/error result.

## M4 — First external repeat-paying agent

Exit evidence:
- buyer not controlled by OCN operator;
- at least 20 successful paid trusted events;
- repeat use across ≥2 sessions;
- spend cap/payment safety preserved;
- no secrets exposed;
- buyer confirms useful output.

Best first users:
- independent agent developer;
- MCP/x402 developer;
- AgentCore developer;
- one Agentic AI Hub startup engineer.

## M5 — First external Shadow Mode workflow + useful trust-gap finding

Exit evidence:
- external workflow trace/adapter;
- no OCN blocking authority during pilot;
- ≥1 finding buyer agrees was useful (stale source, weak evidence, missing authority, beneficiary mismatch, unsupported action, etc.);
- false-positive adjudication captured;
- before/after review evidence.

Best wedges:
- agentic payment;
- government application/decision-support agent;
- enterprise support/write agent;
- procurement/AP agent.

## M6 — First paid design-partner / institutional pilot

Exit evidence:
- signed/paid commercial engagement;
- bounded workflow and success thresholds;
- explicit data/authority boundaries;
- measurement plan;
- design partner: EUR 5k–15k hypothesis, institutional: EUR 25k–50k hypothesis.

## M7 — First customer moves Shadow → Enforcement

Exit evidence:
- buyer authorizes OCN to block a narrow deterministic violation class;
- rollback/manual override exists;
- false-block monitoring active;
- human/consequential authority remains external.

First enforcement classes should be deterministic:
- expired/missing explicit grant;
- beneficiary mismatch;
- amount above intent/mandate;
- detected replay;
- stale source beyond declared policy;
- missing required approval.

## M8 — First repeat deployment

Exit evidence:
- same OCN trust contract used across multiple workflows/agents or authorities;
- integration cost falls on second deployment;
- shared policy/proof registry demonstrates reuse.

Highest leverage: one public IT provider or enterprise agent platform protecting many downstream agents.

## M9 — First measured hosted scale proof

Scale ladder:
1. 100 RPS deterministic event;
2. 1k RPS deterministic event;
3. sustained traffic/autoscaling;
4. failure injection/downstream degradation;
5. p50/p95/p99 + errors + cost published.

No “millions/billions ready” claim until measured architecture supports the extrapolation.

## M10 — Sovereign/customer-controlled deployment validated

Exit evidence:
- same versioned trust semantics run in customer-controlled/VPC/sovereign environment;
- no hidden dependency on OCN-managed sensitive data;
- customer identity/authority/policy providers can remain authoritative;
- deployment/upgrade/telemetry boundaries documented.

## M11 — Independent assurance/security/compliance review

Exit evidence:
- external assessor, security researcher, formal-methods reviewer or relevant audit body reviews defined scope;
- findings publicly summarized where possible;
- remediation tracked;
- A5 only awarded to claim families actually covered by independent attestation.

## M12 — Network business proof

Exit evidence:
- repeat external usage;
- positive gross margin on trusted events or profitable institutional deployment;
- 7/30-day repeat payer signal;
- Shadow → Enforcement conversion;
- second-workflow expansion;
- measurable useful-catch/review-time outcome;
- at least one distribution channel generating usage without founder-led integration.

# Priority use cases to solve first

1. **Payment intent / beneficiary fraud** — immediate financial value and machine-frequency.
2. **Agent action authority** — universal across write-capable agents.
3. **Evidence + freshness** — common to government, legal, compliance, research and finance.
4. **Application/document preflight** — proven public-sector demand.
5. **Procurement/AP guard** — combines entity, invoice, authority, beneficiary, spend and receipts.

Only deepen another capability when a buyer/use signal or trust failure justifies it.
