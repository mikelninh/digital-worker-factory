# HausPilot — Free Cash Flow Playbook

## North star

**Primary goal:** collect the first €1,900 pilot payment as quickly as possible without compromising trust, quality or delivery scope.

Score work by:

`probability of cash × cash amount × speed to cash ÷ delivery burden`

Anything that does not materially help discovery, close, delivery or proof goes to backlog.

---

## 1. Productised offer

### AI Operations Sprint

**Price:** €1,900 net  
**Commercial terms:** 70% (€1,330) to start, 30% (€570) at handover  
**Duration:** 7 calendar days  
**Scope:** one repeatable workflow  
**Client time required:** ~90 minutes total + access/sample cases  

### Promise

> We take one repetitive operational workflow, automate the safe preparation steps with AI, keep consequential decisions behind a human approval gate, and measure the before/after result.

### Deliverables

1. workflow map and baseline
2. measurable success criteria
3. working AI-assisted workflow
4. explicit tool/data permissions
5. human approval boundary
6. 10+ representative test cases, including failure cases
7. audit/evidence trace
8. before/after ROI report
9. recommendation: stop, improve, or expand

### Not included

- unrestricted autonomous actions
- full ERP migration
- company-wide AI transformation
- custom mobile apps
- production integration into every legacy system
- guaranteed labour reduction

These are deliberate scope boundaries, not deficiencies.

## 2. Initial ICP

### Best fit

Berlin/DACH property managers with roughly 5–100 operations staff and recurring work across email, PDFs, tenant requests, maintenance, invoices, owner communication and contractor coordination.

### Buying signals

Add points when a company is:

- currently hiring property-management administrators, assistants or bookkeeping staff
- explicitly talking about digitalisation or process efficiency
- operating multiple property types / locations
- exposing structured tenant forms or service portals
- promising fast response times or transparent communication
- handling high-volume maintenance coordination
- growing its managed portfolio

### Disqualifiers

Do not chase when:

- there is no clearly repeated workflow
- the decision maker will not provide sample cases
- they demand fully autonomous external actions in the pilot
- access/security requirements make a seven-day pilot impossible
- they want speculative strategy rather than an operational implementation
- payment terms exceed 30 days for the first pilot

## 3. First workflow wedge

Default discovery hypothesis:

### Maintenance request triage

**Input:** email/form/message from tenant or owner  
**AI work:** classify request → extract property/unit → detect urgency → retrieve property context → identify missing information → match known service category/vendor → draft response/task  
**Human:** approve consequential external action  
**Output:** ready-to-review case with evidence and next action

Why this wedge:

- easy to understand in 30 seconds
- common across almost every property manager
- measurable volume and handling time
- visible service-quality upside
- can begin in shadow mode
- naturally expands into contractor coordination, invoice review and follow-up

## 4. Discovery call — 25 minutes

### 0–3 min — context

- What kind of portfolio do you manage?
- Which team would feel an operational improvement fastest?

### 3–10 min — find the pain

- Which recurring task makes good employees feel like copy/paste machines?
- What arrives most often by email, form or PDF?
- Where do employees repeatedly look up the same context?
- Which workflow generates the most follow-up?
- What gets delayed when somebody is ill or on holiday?

### 10–15 min — quantify

Capture:

- cases per month
- minutes per case
- number of people touching a case
- common exception rate
- approximate loaded hourly cost
- current response / cycle time

### 15–20 min — constrain

- What must a human always approve?
- Which systems/data may the pilot read?
- Which systems must remain completely untouched?
- Can we get 10–20 anonymised or synthetic representative cases?

### 20–25 min — close

Say:

> I would not automate the whole process. I would start with **[specific preparation step]**, run it in shadow/copilot mode, and measure **[metric]**. If it does not produce enough value, we stop. If it does, you have a working proof rather than a slide deck.

Then propose the €1,900 sprint.

## 6. Objection handling

### “We already have property-management software.”

Good. HausPilot is not trying to replace it. The pilot focuses on the messy work **between** inboxes, documents, context and the action your software expects.

### “AI makes mistakes.”

Correct — which is why the model does not own authority. The pilot separates AI interpretation from deterministic permissions, evidence checks and human approval.

### “We cannot give you tenant data.”

Start with anonymised/synthetic cases or run locally against deliberately limited fields. A pilot does not require unrestricted production access.

### “We need to discuss it internally.”

Ask: “Which concern will decide the answer — ROI, data protection, integration, or team adoption?” Then provide only the proof needed for that concern.

### “€1,900 is too much for a test.”

If the workflow cannot plausibly return €1,900 within a few months, it is the wrong workflow and we should not run the sprint.

### Pilot

HausPilot will prepare `[specific output]` by reading `[approved inputs]`, performing `[safe steps]`, and stopping for human approval before `[consequential action]`.

### Success

Baseline vs pilot:

- handling time per case
- percentage of cases correctly prepared
- missing-information detection
- escalation quality
- human correction rate

### Commercials

€1,900 net. 70% at kickoff, 30% at handover. One workflow. Seven days.

## 8. Delivery SOP

### Day 1 — map

- record exact workflow
- capture baseline
- collect representative cases
- label decisions vs preparation work
- define forbidden actions

### Day 2 — contract

Create worker specification:

- inputs
- allowed tools
- evidence requirements
- required outputs
- human gates
- escalation conditions
- loop budget

### Day 3 — build

Implement smallest end-to-end path. Do not optimise edge cases before the happy path works.

### Day 4 — adversarial test

Include:

- missing tenant/unit identifier
- duplicate request
- contradictory data
- unavailable contractor
- urgent vs non-urgent ambiguity
- malformed attachment
- instruction injection inside email/PDF
- unsupported request category
- attempted action without approval

### Day 5 — shadow

Run cases without external actions. Record correction rate and missing context.

### Day 6 — copilot

Put proposed actions in front of a human. Measure time saved and correction burden.

### Day 7 — proof

Deliver:

- live workflow
- trace/eval examples
- baseline vs pilot
- failure cases
- ROI estimate
- recommendation
